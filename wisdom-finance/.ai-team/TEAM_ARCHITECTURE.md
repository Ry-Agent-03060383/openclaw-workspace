## 三、协同流程

### 3.1 标准交付流水线

```
原始需求 → Hermes解析 → 派发P01 → PRD输出 
→ Hermes验收 → 派发P02 → 架构设计 
→ Hermes验收 → 并行派发P03,P04,P05 → 代码产出 
→ 派发P06 → 测试报告 → 派发P08 → 审查报告 
→ 派发P09 → 文档输出 → 派发P10 → 安全报告 
→ 派发P11 → 发布就绪 → 派发P12 → 部署上线
```

### 3.2 异常处理机制

| 异常类型 | 上报路径 | 处理方式 |
|----------|----------|----------|
| 需求不明确 | P01 → Hermes | Hermes 与需求方确认后补充 |
| 技术方案争议 | P02 → Hermes | Hermes 组织多方案评估决策 |
| 代码质量不达标 | P08 → Hermes | Hermes 退回 P03/P04 修改 |
| 测试用例失败 | P06 → Hermes | Hermes 判断缺陷归属并派发修复 |
| 安全漏洞 | P10 → Hermes | Hermes 紧急派发修复并升级优先级 |
| 发布回滚 | P11 → Hermes | Hermes 触发回滚并记录事故 |

### 3.3 交付质量标准

| 维度 | 标准 | 验收人 |
|------|------|--------|
| PRD 完整度 | 含功能描述/验收标准/边界条件 | Hermes |
| 架构文档 | 含 ER图/系统架构图/技术选型说明 | Hermes |
| 代码规范 | 通过 ESLint/Prettier/Checkstyle | P08 |
| 测试覆盖率 | 单元测试 ≥ 80%，E2E 覆盖核心流程 | P06 |
| 安全审计 | 无高危漏洞，OWASP Top 10 合规 | P10 |
| 文档完整 | API 文档 100% 覆盖，用户手册完整 | P09 |

## 四、团队生效规则

1. **永久绑定**：12 个专项 Agent 一经注册自动纳入 Hermes 专属团队池，后续所有项目默认调用该固定团队
2. **岗位唯一性**：一岗一责，禁止兼任，禁止跨岗越权
3. **权限锁定**：仅 Hermes 主控拥有任务分发/验收/纠错/重调/归档权限
4. **标准化初始化**：所有子 Agent 统一遵循全局调度工作流、统一交付标准、统一报错重跑机制
5. **版本追溯**：每次交付记录版本号、责任 Agent、时间戳，支持全链路追溯
