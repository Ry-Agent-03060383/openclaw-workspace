# 全局调度工作流与协同规则

> 版本: v1.0
> 生效: 永久
> 适用范围: Hermes 主控 + 12 专项执行 Agent

---

## 1. 任务生命周期

```
┌──────────────────────────────────────────────────────┐
│                    任务生命周期                         │
└──────────────────────────────────────────────────────┘

INBOX → ASSIGNED → IN_PROGRESS → REVIEW → ACCEPTED → CLOSED
                                      ↓
                                   REJECTED → REASSIGNED → IN_PROGRESS
                                      ↓
                                   ABORTED → ARCHIVED
```

### 阶段定义

| 阶段 | 说明 | 负责人 |
|------|------|--------|
| INBOX | 任务接收池，未分配 | Hermes |
| ASSIGNED | 已指派给具体岗位 Agent | Hermes |
| IN_PROGRESS | 执行中 | 对应岗位 Agent |
| REVIEW | 提交验收 | 对应岗位 Agent → Hermes |
| ACCEPTED | 验收通过 | Hermes |
| REJECTED | 验收驳回，附驳回原因 | Hermes |
| ABORTED | 任务终止（需求变更/取消） | Hermes |
| CLOSED | 任务闭环 | Hermes |

## 2. 岗位调度规则

### 2.1 上游依赖优先
- P01 未完成 → 禁止启动 P02
- P02 未完成 → 禁止启动 P03/P04/P05
- P03/P04/P05 未完成 → 禁止启动 P06
- P06 未完成 → 禁止启动 P08
- P08 未完成 → 禁止启动 P09
- P09 未完成 → 禁止启动 P10
- P10 未完成 → 禁止启动 P11
- P11 未完成 → 禁止启动 P12

### 2.2 并行执行规则
- P03、P04、P05 可在 P02 验收后并行执行
- P07 可与 P03/P04 并行执行（基础设施先行）

### 2.3 依赖超时机制
- 上游阶段超过预估工时 2 倍 → 自动上报 Hermes 仲裁
- Hermes 可在超时后执行: A) 延长工时 B) 替换 Agent C) 回退重做

## 3. 报错重跑机制

### 3.1 异常分类与处理

| 异常类型 | 处理方式 | 重跑策略 |
|----------|----------|----------|
| 编译错误 | Agent 自行修复后重提验收 | 自检修正 |
| 测试失败 | Agent 修复后重新提交 | 自检修正 |
| 审查不通过 | 根据审查意见修复后重新提交审查 | 同行修正 |
| 验收驳回 | 根据驳回原因修复后重新提审 | Hermes 再验 |
| 外部依赖失败 | 上报 Hermes 等待依赖就绪 | 依赖等待 |
| 不可恢复错误 | 上报 Hermes 标记 ABORTED | 人工仲裁 |

### 3.2 重跑次数上限
- 同一任务最多重试 3 次
- 超过 3 次 → 自动上报 Hermes 升级处理
- Hermes 可决定: 终止任务 / 拆分任务 / 更换 Agent

## 4. 任务分配规则

### 4.1 分配策略
- Hermes 根据任务类型自动匹配对应岗位 Agent
- 多个同类任务按先入先出（FIFO）分配
- 紧急任务可插队（Hermes 手动标识 PRIORITY）

### 4.2 负载均衡
- 每个 Agent 同时最多执行 1 个活跃任务
- 新任务排队等待当前任务完成
- Hermes 可查看全队列状态并手动调整

## 5. 交付验收标准

### 5.1 通用标准
- 所有交付物必须包含版本号和 Agent 签名
- 代码交付必须通过静态检查（ESLint/Checkstyle）
- 测试覆盖率 ≥ 80%（核心路径 ≥ 90%）
- 无高危漏洞（CVSS ≥ 7.0 零容忍）

### 5.2 验收流程
```
Agent 提交 → Hermes 初审（格式/完整性）
           → 通过 → Code Review（P08参与）
           → 通过 → 安全审查（P10参与，按需）
           → 通过 → Hermes 终验 → ACCEPTED
```

### 5.3 打分制
| 等级 | 标准 | 动作 |
|------|------|------|
| S (95-100) | 零缺陷、文档完善、性能优化 | 直接 ACCEPTED |
| A (80-94) | 少量 minor 问题 | 修复后 ACCEPTED |
| B (60-79) | 有 major 问题 | REJECTED，修复重提 |
| C (&lt;60) | 严重缺陷/缺失 | ABORTED，重新评估 |

## 6. 异常上报机制

### 6.1 Agent 上报格式
```json
{
  "type": "DEPENDENCY_FAILURE",
  "agent": "P04",
  "taskId": "TASK-2026-06-17-001",
  "severity": "BLOCKER",
  "description": "外部支付网关 API 不可用",
  "impact": "贷款申请提交功能无法完成",
  "suggestedAction": "等待支付网关恢复或切换备用通道",
  "timestamp": "2026-06-17T10:30:00Z"
}
```

### 6.2 上报路径
```
Agent 发现异常 → 写入异常日志 → Hermes 异常队列
              → 普通异常 → 排队处理（15min 内响应）
              → BLOCKER/CRITICAL → 即时通知（Hermes 立即响应）
```

## 7. 沟通规范

### 7.1 岗位间通信
- Agent 间不直接通信，全部经过 Hermes 转发
- 上下游任务流转由 Hermes 统一调度
- 禁止 Agent 之间私下传递数据或指令

### 7.2 汇报格式
每个 Agent 交付时必须包含:
```
任务ID: TASK-{date}-{seq}
岗位: P0X - {岗位名称}
状态: COMPLETED / FAILED
交付物:
  - {文件名} ({文件路径})
  - ...
耗时: {实际工时}/{预估工时}
自检结果: PASS / FAIL（附原因）
备注: {可选补充说明}
```

## 8. 版本管理规则

### 8.1 版本号策略
- 格式: `v{major}.{minor}.{patch}-{build}`
- major: 架构变更/不兼容 API 变更
- minor: 新功能/兼容 API 变更
- patch: Bug 修复/小优化
- build: 每日构建递增

### 8.2 分支策略
- `main` — 生产就绪代码（仅 P11 可操作合并）
- `develop` — 开发集成分支
- `feature/{task-id}` — 功能分支
- `hotfix/{issue-id}` — 紧急修复分支

## 9. 质量门禁

| 检查项 | 门禁标准 | 违规处理 |
|--------|----------|----------|
| 编译 | 零错误 | 拒绝合并 |
| Lint | 零 error | 拒绝合并 |
| 单元测试 | 通过率 100% | 拒绝合并 |
| 覆盖率 | ≥ 80% | 警告（≥60%）/ 拒绝（&lt;60%）|
| 安全扫描 | 零高危漏洞 | 拒绝发布 |
| API 文档 | 100% 覆盖率 | 拒绝发布 |
| 代码审查 | 至少 1 人 Approved | 拒绝合并 |
