## 1. 业务背景和目标

智慧金服平台已完成后端 15 个核心模块的开发（91 个 Java 文件），前端框架搭建完成（33 个 Vue/TS 文件）。当前阶段的核心目标是：

1. **质量加固**：后端测试覆盖率从当前 <5% 提升至 ≥80%
2. **前端完整**：各角色页面从骨架阶段完善到可交互、数据驱动的完整 UI
3. **核心流程打穿**：企业发布融资需求 → 银行匹配 → 审批 → 放款 → 贷后监控全链路

## 3. 用户故事

### US-01: 企业用户查看仪表盘
> **作为** 中小企业用户  
> **我希望** 登录后看到定制的 Dashboard  
> **以便** 我快速了解贷款进度、信用评分和待办事项

**验收标准**:
- [ ] 显示企业名称和基本信息
- [ ] 显示贷款申请状态统计（待审/进行中/已放款）
- [ ] 显示信用评分和等级
- [ ] 显示待办事项列表（待补充材料、待确认等）
- [ ] 支持跳转到对应功能页

### US-02: 银行用户匹配产品
> **作为** 银行客户经理  
> **我希望** 系统根据企业融资需求自动匹配适合的贷款产品  
> **以便** 我快速响应企业融资申请

**验收标准**:
- [ ] 系统根据企业规模、行业、金额自动匹配产品
- [ ] 匹配结果按匹配度排序
- [ ] 支持银行手动调整匹配结果
- [ ] 匹配结果含利率、额度、期限信息

### US-03: 贷款全流程审批
> **作为** 企业用户  
> **我希望** 在线提交贷款申请并实时跟踪审批进度  
> **以便** 我快速获得融资

**验收标准**:
- [ ] 企业可选择匹配的贷款产品发起申请
- [ ] 申请自动流转至对应银行审批队列
- [ ] 银行可查看申请详情并执行审批操作（通过/驳回/补充材料）
- [ ] 企业可实时查看审批状态
- [ ] 通过后进入签约放款流程

### US-04: 后端测试覆盖
> **作为** 测试工程师  
> **我希望** 所有 Service 层都有单元测试覆盖  
> **以便** 确保业务逻辑正确性和回归安全性

**验收标准**:
- [ ] 每个 Service 类有对应的 Test 类
- [ ] 使用 JUnit 5 + Mockito
- [ ] 核心业务方法覆盖率 ≥80%
- [ ] 异常路径和边界条件有测试用例
- [ ] mvn test 全部通过

## 5. 边界条件和异常处理

| 场景 | 处理方式 |
|------|----------|
| 贷款额度超过产品上限 | 审批前提示超限，需银行特批 |
| 企业信用评分低于门槛 | 自动拒绝并推送提升建议 |
| 银行匹配结果为空 | 展示无匹配产品提示 + 推荐相近补充产品 |
| 审批超时未处理（3天） | 自动升级通知银行主管 |
| API 调用失败 | 前端统一 error handler 展示友好提示 |
| 数据加载中 | 展示骨架屏/skeleton 加载态 |
| 空数据状态 | 展示空状态插图和引导文案 |
